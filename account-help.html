三步完成登录

约 20 秒
  1. 打开本站任意页面，点右上角的 「登录」（手机上在右下角）。
  2. 在输入框里填 手机号或邮箱（系统会自动识别），点 「获取验证码」。
  3. 把收到的验证码填进去（邮箱通常是 6-8 位） → 点 「登录 / 注册」，完成。首次登录会自动创建账号。
登录面板示意 手机号或邮箱：138****8888 或 you@qq.com 验证码：______　[ 获取验证码 ] [ 登录 / 注册 ] 使用密码登录 ›　·　未注册将自动创建账号，登录即注册
没有账号也能直接登录：验证码通过后会自动帮你创建，不需要单独点"注册"。 邮箱和手机号是两个独立账号，用哪个登录就看到哪个的数据，请固定用一种。
登录后右上角会显示你的账号（邮箱如 te***@qq.com、手机如 138****5678），点它能看到同步状态和退出登录。

换设备前先看这条：同步规则是"最后写入的胜出"。请先在主力设备（数据最多的那台）登录并确认同步完成， 再去其它设备登录。反过来做，空数据的设备可能把已有数据覆盖掉。
3

换设备怎么恢复

20 秒

在新设备（或换浏览器、清过缓存后）打开站点，用同一个邮箱 / 手机号再登录一次，数据会自动从云端拉回来。

判断有没有恢复成功：点右上角账号 → 面板里各项显示 「刚刚」（绿点）即正常。

常见问题

收不到短信验证码

① 等 60 秒后再点一次（同一号码 30 秒内只能发 1 条）；② 检查手机号有没有填错；③ 一个号码一天最多收 30 条；④ 长期收不到多半是短信额度用完了，改用邮箱登录即可。

收不到邮件验证码

① 先看垃圾邮件 / 广告邮件；② 等 60 秒后重试；③ 确认邮箱地址没拼错（尤其 qq.com / gmail.com 后缀）。

手机号和邮箱都能用吗

是的。登录框同时支持手机号和邮箱，输入后会自动判断。但短信验证码需要额外购买短信服务，日常推荐使用邮箱登录（完全免费）。

邮箱和手机号是同一个账号吗

不是。它们是两个独立账号，各自存一份数据。请固定用一种方式登录，否则会看到两套不同的进度。

提示"尚未配置 Supabase"

这是站长还没开通账号登录功能，把这一页发给站长看第 5 节。

数据没同步过去

确认你打开的是该功能自己的页面（见第 2 节表格），并且面板里能看到那一项的状态。也可以点面板里的 强制上传 手动推一次。

退出登录后数据会没吗

不会。退出只是停止同步，本机和云端的数据都还在，重新登录即可继续。

我的数据会被别人看到吗

不会。每个账号的数据互相隔离，只有你自己的账号能读写；站长作为管理员可以查看，仅用于排查问题和了解学习进度。

5

开通账号登录（邮箱 + 手机号）

约 15 分钟

用 Supabase 作为后端（永久免费层，无安全域名白名单限制，靠 anon key + Row Level Security 隔离）。它原生支持邮箱验证码登录；手机号短信验证码也能用，但短信需要另购 SMS provider，通常会产生费用，建议测试用户一律走邮箱。

  1. 注册 Supabase，New Project（免费层即可，地域任选）。
  2. 左侧 Project Settings → API，复制 Project URL 与 anon public key（可安全暴露在前端）。
  3. 把这两项填进 assets/js/cb-config.js：
supabaseUrl: 'https://xxxx.supabase.co',   // 你的 Project URL
anonKey:     'eyJhbGci...',                    // 你的 anon public key

费用：永久免费，邮箱登录 0 元

项目费用说明
Supabase 免费层0 元50,000 MAU、500MB Postgres、5GB 流量/月，几个测试用户完全够用，无到期时间。
邮箱登录0 元验证码发到邮箱（或密码登录），不产生任何费用。测试期一律让用户走这个。
手机号短信按量付费需在 Supabase 接入 Twilio 等 SMS provider，按条计费；免费层默认发不了短信 → 手机号通道会提示失败，改用邮箱即可。
两个要注意的点：
① 免费层不卡安全域名白名单（靠 anon key + RLS 隔离），所以 GitHub Pages 上线也不会 CORS 报错 —— 这正是从 CloudBase 换过来的原因。
② 登录态会持久化在浏览器 localStorage，用户不会每次打开都收验证码，实际邮件/短信消耗远低于直觉。
6

数据隔离与管理员

在 Supabase 左侧 SQL Editor 里执行下面建表 + 权限（Row Level Security）语句：

create table if not exists sync_data (
  id          text primary key,
  user_id     uuid not null,
  scope       text not null,
  data        jsonb,
  updated_at  bigint
);
alter table sync_data enable row level security;

-- 每个人只能读写自己的数据
create policy "own_rw" on sync_data
  for all
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);

-- 管理员可读全部（把下面的 UUID 换成你自己的）
create policy "admin_read" on sync_data
  for select
  using (auth.uid() = '这里填你的UUID');

含义：每个人只能读写自己的数据；填进 adminUids 的账号（UID 即 Supabase 的 user id）可以多读一份他人数据（管理员）。

  1. 先用你的邮箱登录 → 右上角账号面板底部复制 UID（形如 UUID）。
  2. 把该 UUID 填进上面第二条 policy，同时填进 cb-config.js 的 adminUids 数组。
  3. 打开 /admin.html，输入某个用户的 UID 就能查看他的数据；也可以在 Supabase 控制台的 sync_data 表里按 user_id 筛选、导出。
RLS policy 保存后立即生效；如果立刻读写报权限错误，检查 anon key 是否对应同一个项目、以及是否执行了 enable row level security。

附录：GitHub 仓库同步（备用通道）

账号登录之外，还保留了一条把数据存进自己 GitHub 私有仓库的通道，适合站长自用或当备份。在登录面板底部展开「其他登录方式（GitHub 备用）」使用。

  1. 在 GitHub 建私有空仓库（建议名 mrcubessr-site-sync，勾 Private + Add a README）。
  2. 生成 fine-grained 令牌：只选这一个仓库，权限只勾 Contents: Read and write。
  3. 回到面板填 用户名 / 仓库名 / 令牌 → 连接并开通。
两条通道同一时间只用一条：邮箱/手机号登录后优先用 Supabase；退出该账号才会走 GitHub。
