账号登录与跨设备同步 · 使用教程

开通账号后，站内各功能的数据会存进你自己的 GitHub 私有仓库，换手机、换电脑、清缓存都不丢。 整个过程只要三步、约 3 分钟：建仓库 → 生成令牌 → 回站点登录。 本站是纯静态站点、没有后端服务器，所以账号用 GitHub 当"云盘"，数据只属于你。

1

在 GitHub 建一个私有仓库

约 1 分钟

打开 github.com/new（没有 GitHub 账号先免费注册一个），按下面填：

New repository 页面填法示意 Owner: 你的用户名　Repository name: fto-site-sync ○ Public　● Private（务必选私有） ☑ Add a README file（勾上，保证仓库非空） [ Create repository ]
  • Repository name：填 fto-site-sync。想改别的名字也行，登录时填一致即可。
  • Private：必须选私有，数据只有你看得到。
  • Add a README file：勾上，空仓库有时会导致首次写入失败。
仓库建好后先别关，下一步马上要用它。
2

生成专用令牌（只授权这一个仓库）

约 1 分钟

打开 Settings → Developer settings → Personal access tokens → Fine-grained tokens，点 Generate new token。

Token name随便填，例如 fto-site-sync
Expiration建议 90 天或 1 年。到期后重新生成一个再登录一次即可
Repository access● Only select repositories → 只勾选刚才建的 fto-site-sync
PermissionsRepository permissions → 找到 Contents → 设为 Read and write
权限别多给。只勾 Contents: Read and write 就够了（Metadata: Read-only 是系统自动带的）。 千万不要勾"All repositories"，那等于把你的全部仓库交给浏览器。

点 Generate token 后，页面上会出现一串以 github_pat_ 开头的字符串 —— 立刻复制保存，它只显示这一次，关掉就看不到了。

3

回站点登录并开通

约 30 秒

打开本站任意页面，右上角有一个 「登录同步」 按钮（手机上是右下角浮动按钮），点它：

账号面板 · 方式一「手动开通」填法示意 GitHub 用户名：你的 GitHub 用户名（不是邮箱） 同步仓库：fto-site-sync 访问令牌：github_pat_xxxx（粘贴刚才复制的） [ 连接并开通 ]
  1. GitHub 用户名：填用户名，不是邮箱。
  2. 同步仓库：默认 fto-site-sync，跟你建的仓库名保持一致。
  3. 访问令牌：粘贴第 2 步复制的令牌。
  4. 点 连接并开通，成功后右上角会变成 @你的用户名。
成功后本站会自动把当前页面的数据上传一次。之后每次改动会自动同步，不用手动点。
顺序很重要：先在数据最多的那台设备上登录。 同步规则是"最后写入的胜出"。如果你先拿一台空数据的设备登录，它会把空数据传上去； 等你再用有数据的设备登录时，可能被判定为"远端更新"而覆盖掉本地数据。
正确顺序：主力设备登录 → 确认上传完成 → 再去其它设备登录。
4

确认同步成功

10 秒

点右上角 @用户名 打开面板，会列出本页各功能的同步状态：

  • 绿点 + 刚刚：同步正常。
  • 黄点 + 同步中…：正在传，稍等几秒。
  • 红点 + 出错：看第 7 节排查。

更直接的验证：打开你的 GitHub 仓库，应该能看到自动生成的文件，例如 srs.json、timer.json，提交记录写着 fto-site data sync。

面板里的三个按钮：立即拉取（把云端拉回来）、强制上传全部（本页数据覆盖云端）、强制下载全部（云端覆盖本机）。 一般不用管，遇到数据对不上时再用来手动纠正。
5

换设备 / 换浏览器怎么恢复

30 秒

在新设备（或新浏览器、清过缓存之后）上，重复第 3 步：打开站点 → 登录同步 → 填同样的用户名、同样的仓库名、同样的令牌。

登录后会自动从云端把数据拉回来，各功能状态变成"刚刚"即恢复完成。

令牌只会显示一次，建议生成时存进密码管理器。忘了令牌不用慌：重新生成一个，用它重新登录即可，仓库里的数据不受影响。

7

常见问题排查

提示"仓库不存在，且当前令牌无法自动创建"

检查三件事：①仓库名是否拼错（区分大小写）；②仓库是不是建在别的用户名/组织下；③令牌的 Repository access 是否勾选了这个仓库。

最快的办法：回 GitHub 打开仓库，看地址栏是不是 github.com/你的用户名/fto-site-sync。

提示"无法访问仓库 (401/403)"

令牌无效或权限不够。常见原因：①复制时少了开头或结尾；②令牌已过期；③Repository access 没勾这个仓库；④Contents 权限不是 Read and write。

重新生成一个令牌再试是最快的解法。

登录成功了，但状态一直显示"出错"

打开 GitHub 仓库看有没有生成 json 文件。如果一直没有，多半是令牌过期或权限不足（见上一条）。

如果文件有、但状态报错，刷新页面重试；仍不行就把报错文字发给我。

数据没同步过去

确认你当前打开的是该功能自己的页面（见第 6 节），并且面板里能看到那一项的状态。

也可以点面板里的 强制上传全部 手动推一次。

退出登录后数据会没吗

不会。退出只是停止同步，本机数据和云端仓库里的数据都还在。重新登录即可继续。

8

安全须知

  • 本站是纯静态站、没有后端，令牌只存在你这台设备的浏览器里，不会传到任何服务器。
  • 务必使用只授权那一个仓库的 fine-grained 令牌，不要用全权限的经典令牌。
  • 公用电脑登录后记得退出；退出登录会清除本机令牌。
  • 令牌到期前的最后一刻都可以续：重新生成 → 重新登录，数据不受影响。
数据同步依赖 GitHub 的服务可用性。重要数据建议偶尔用各功能自带的导出备份另存一份。
