账号登录 · 邮箱或手机号

三步完成登录

约 20 秒
  1. 打开本站任意页面，点右上角的 「登录」（手机上在右下角）。
  2. 面板顶部选 「邮箱」 或 「手机号」（默认邮箱，免费且不收短信）。
  3. 填邮箱/手机号 → 点 「获取验证码」 → 把收到的 6 位验证码填进去 → 点 「登录 / 注册」，完成。
登录面板示意 [ 邮箱 免费·推荐 ] [ 手机号 收短信 ] 邮箱地址：you@example.com 验证码：______　[ 获取验证码 ] [ 登录 / 注册 ]
没有账号也能直接登录：验证码通过后会自动帮你创建，不需要单独点"注册"。 邮箱和手机号是两个独立账号，用哪个登录就看到哪个的数据，请固定用一种。
登录后右上角会显示你的账号（邮箱如 te***@qq.com、手机如 138****5678），点它能看到同步状态和退出登录。

各功能在自己的页面里同步。比如在记忆卡页面，面板只显示"记忆卡"；想同步计时成绩，打开计时器页面即可（已登录状态下自动同步）。
换设备前先看这条：同步规则是"最后写入的胜出"。请先在主力设备（数据最多的那台）登录并确认同步完成， 再去其它设备登录。反过来做，空数据的设备可能把已有数据覆盖掉。
3

换设备怎么恢复

20 秒

在新设备（或换浏览器、清过缓存后）打开站点，用同一个邮箱 / 手机号再登录一次，数据会自动从云端拉回来。

判断有没有恢复成功：点右上角账号 → 面板里各项显示 「刚刚」（绿点）即正常。

4

常见问题

收不到短信验证码

① 等 60 秒后再点一次（同一号码 30 秒内只能发 1 条）；② 检查手机号有没有填错；③ 一个号码一天最多收 30 条；④ 长期收不到多半是短信额度用完了，改用邮箱登录即可。

收不到邮件验证码

① 先看垃圾邮件 / 广告邮件；② 等 60 秒后重试；③ 确认邮箱地址没拼错（尤其 qq.com / gmail.com 后缀）。

邮箱和手机号是同一个账号吗

不是。它们是两个独立账号，各自存一份数据。请固定用一种方式登录，否则会看到两套不同的进度。

提示"尚未配置 CloudBase"

这是站长还没开通账号登录功能，把这一页发给站长看第 5 节。

数据没同步过去

确认你打开的是该功能自己的页面（见第 2 节表格），并且面板里能看到那一项的状态。也可以点面板里的 强制上传 手动推一次。

退出登录后数据会没吗

不会。退出只是停止同步，本机和云端的数据都还在，重新登录即可继续。

我的数据会被别人看到吗

不会。每个账号的数据互相隔离，只有你自己的账号能读写；站长作为管理员可以查看，仅用于排查问题和了解学习进度。

5

开通账号登录（邮箱 + 手机号）

约 15 分钟

用腾讯云开发 CloudBase 作为后端。它原生支持邮箱验证码与手机号短信验证码两种注册登录，两者流程一致、可同时开启。

  1. 开通 云开发 CloudBase，新建环境，地域选「上海」（短信仅支持上海地域）。
  2. 开启登录方式：控制台 → 身份认证 → 登录方式 → 把 邮箱验证码 和 短信验证码 都开启（只想省事可只开邮箱）。
  3. 加安全域名：环境配置 → 安全配置 → 添加你的站点域名（约 10 分钟生效）。不加会报 CORS 错误。
  4. 生成 Publishable Key：环境 → API Key 配置 → 生成（只能生成一次，保存好）。
  5. 把这两项填进 assets/js/cb-config.js：
env: '你的环境ID',                    // 如 fto-site-3gxxxxxxxx
publishableKey: '你的 Publishable Key',

费用：环境免费，只有短信要钱

项目费用说明
云开发环境0 元免费体验版 3000 资源点/月，覆盖数据库读写与登录调用，几个测试用户完全够用；有效期 6 个月，到期可续。
邮箱验证码0 元完全不走短信通道，不产生任何费用。测试期建议让用户走这个。
短信验证码首月 100 条免费
之后约 5 分/条		短信资源包 1000 条 50 元 / 1 万条 470 元。限流：同号 30 秒 1 条、每天最多 30 条。
两个要注意的点：
① 免费体验版官方说明「暂不支持加购扩展资源包」，而短信资源包属于扩展资源包 —— 也就是说免费环境可能买不了短信包，首月 100 条用完后要么升个人版（19.9 元/月）才能加购，要么改用邮箱。保险起见，测试用户一律走邮箱。
② 登录态会持久化（refresh token 约 30 天），用户不会每次打开都收短信，实际短信消耗远低于直觉。
6

数据隔离与管理员

在控制台 → 文档型数据库 → 新建集合 sync_data，权限管理切到安全规则，填：

{
  "read":  "doc.userId == auth.uid || auth.uid in ['这里填你的UID']",
  "write": "doc.userId == auth.uid"
}

含义：每个人只能读写自己的数据；填进列表的 UID 可以读全部（管理员）。

  1. 先用你的邮箱或手机号登录 → 右上角账号面板底部复制 UID。
  2. 把 UID 填进上面规则里，同时填进 cb-config.js 的 adminUids 数组。
  3. 打开 /admin.html，输入某个用户的 UID 就能查看他的数据；也可以在控制台的 sync_data 集合里按 userId 筛选、导出整表。
安全规则修改后约 2–5 分钟生效；如果立刻读写报权限错误，等一会儿再试。

附录：GitHub 仓库同步（备用通道）

账号登录之外，还保留了一条把数据存进自己 GitHub 私有仓库的通道，适合站长自用或当备份。在登录面板里展开「高级：用 GitHub 仓库同步」使用。

  1. 在 GitHub 建私有空仓库（建议名 fto-site-sync，勾 Private + Add a README）。
  2. 生成 fine-grained 令牌：只选这一个仓库，权限只勾 Contents: Read and write。
  3. 回到面板填 用户名 / 仓库名 / 令牌 → 连接并开通。
两条通道同一时间只用一条：手机号登录后优先用 CloudBase；退出手机号账号才会走 GitHub。
