## [2.0.14] — 2026-10-16（修复 · hold-to-start 计时三处缺陷；矩阵/看板视觉重构：快慢改字色、卡片去公式）

用户实际使用「高阶翼棱」练习页反馈：计时器延时不灵敏、停表后第一次总不显示、看图页面要刷新才有效果；并提出矩阵布局保留、快慢改用字体颜色体现、卡片不写公式直接显示位置码（B行M列 → BM）。修复与改造**三页同步**（`tools/4bld/wing.html` 翼棱、`tools/4bld/index.html` 440 中心块、`tools/scramble-uf440/index.html` UF440）。

**修复**
- **计时器长按不灵敏（根因：repeat 分支清掉计时器且不重建）**：`pKeydownHold()` 中「长按中保持」分支原实现为 `clearTimeout(pPrep)`——真实浏览器长按会持续派发 `keydown`（autorepeat），repeat 到来时把 prep 计时器清掉且不重建，导致**按住再久都到不了 green、松手即取消**，完全无法开始计时。现改为该分支直接返回（幂等，等原计时器自然到点）。另注意：绑定处的 `!e.repeat` 过滤不可靠（浏览器只对真实按住置 `repeat`），防御必须落在 `pKeydownHold` 自身。
- **停表后成绩不显示（根因：只重绘看板不重绘矩阵）**：`pStopTimer()` 原先只调用 `renderBoard()`，在矩阵总览视图下成绩虽已写入 localStorage，但格子 / KPI / TOP10 不更新，表现为「计时后不显示，要刷新页面才生效」。现改为 `renderCurrent()` 按当前视图重绘；删除成绩、清空成绩两处同步修正。
- **响应速度**：hold 时长 500ms → 300ms（仍足够避免误触）。
- **翼棱新增全屏计时器点击启停**：全屏计时器（`#c4-fs-timer`）也可点击开始/停止，与空格键等效。

**视觉重构**
- **快慢改用字体颜色体现**：`colorByRatio()` 由「连续渐变色背景 + 按亮度反算字色」改为输出 **7 阶离散字色** `var(--spd-t0..6)`（JS 只计算档位索引，色值全部走 CSS 变量；深色主题用亮色系、浅色主题同色相压暗一档，**切换主题即时生效、无需重渲染**）。连续渐变色背景仅保留给仪表盘图例。矩阵格与看板卡片的内联样式**只保留 `color`** 不再写 `background`——**底色表达「是否练过」，字色表达「快慢」**，两层信息不互相干扰。
- **卡片不再显示公式，直接显示位置码**：练习总览卡片去掉公式文本，位置码放大居中（如 B行M列显示 **BM**，与矩阵行列一眼对应；翼棱三字母码 `A+XY` 去掉缓冲前缀 A 显示两位）；完整码与公式仍保留在悬停提示中。矩阵总览格内仍直显公式，但公式不再使用内部分节着色（避免覆盖快慢字色），详情/练习浮层中的公式着色不受影响。
- **`sw.js` 未改**：三页均不在计时器 PWA 的 `APP_SHELL` 清单内。
- 验证：新增 `verify_fix_2014.py`（三页 × 长按含 repeat 可启动 / 松开即开跑 / 停表后矩阵 KPI 立即更新 / 字色与卡片形态 / 一屏铺满 / 0 报错）**30/30 全过**；回归 `verify_wing_matrix.py`、`verify_uf440_matrix.py`（断言随新口径更新）及 `verify_refs_4bld.py` 24/24、`verify_refs_multires.py` 8/8、`verify_refs_pmodal.py` 25/25 全绿；深浅双主题截图核对可读性。

## [2.0.10] — 2026-10-16（修复 · 翼棱公式覆盖 420 → 506，补全含 G/H 情况的旋转解析）

- **问题**：v2.0.9 的翼棱页只收录了以缓冲 `A`（UFr）为**首字母**的 `420` 条码，误把含 `G`/`H`（URb / RUf 两个翼块位）的 `86` 个情况当成"库无覆盖"剔除——例如 `ABG` 在页面里搜不到。而用户口径要求：**缓冲固定、其余位置全排列**，即 `23×22 = 506` 个有向情况必须全部有公式。
- **根因**：blddb 的 3 字母码表示三循环，同一循环可写作 3 种旋转（`ABC`/`BCA`/`CAB`）；blddb 把含 `G`/`H` 的情况存成了**以 `G`/`H` 为首字母**的码（如 `{A,B,G}` 存为 `GAB`/`GBA`）。其官网 `wing.js` 的 `algSearch` 正是靠这三次旋转回退来查找，只取首字母 = `A` 的码必然漏掉这 86 个。
- **修复**：重写抽取脚本 `extract_blddb_wing.py`——对每个缓冲-A 情况 `(A X Y)` 依次尝试 `(A X Y)` / `(X Y A)` / `(Y A X)` 三次旋转去库查，命中即用；断言 `506` 个情况**全部命中（缺失 = 0）**。重生 `wing-algs.tsv`（`420 → 506` 行，原 420 行内容不变，纯增 86 行）、`wing-data.js`（`506` 情况 / `2751` 条公式，主公式 + 备选；生成器 `gen-wing-data.py` 的 `ORDER` 扩到 23 个次位置字母，含 `G`、`H`）。
- **页面同步**：矩阵由 `21×21` 扩到 `23×23`（`wing.css` 网格列数、`wing.html` 表头文案"21 个次位置"→"23 个次位置"、提示语改为"含 G/H（UR 棱）情况，已用三循环旋转解析补全"）；**搜索加旋转容错**（输入 `ABG` / `GAB` / `BAG` 任一旋转均可命中同一情况）；看板 `MIN_CELL` `32 → 28`，让 506 卡在 1440×900 下仍一屏铺满。
- **未改** `sw.js`（`wing.html` / `wing.css` / `wing-data.js` 均为 `tools/4bld/` 独立工具页资源、不在计时器 PWA 的 `APP_SHELL` 缓存清单内，按规矩无需递增 `CACHE`）。
- 验证：本地 `1920×1080` / `1440×900` / `1366×768` / `640×900` 四档共 28 项全 PASS（含"搜索 ABG 命中""搜索 GAB 旋转命中 ABG""详情 ABG 含公式""控制台 0 报错"）。

## [2.0.2] — 2026-10-10（补丁 · 修复备份导入整份失败 + 往返导入翻倍）

> 数据找回过程中的连带修复。用户在恢复 23,895 条成绩的备份时导入报「无法解析文件内容」，
> 顺藤摸出的两个既有 bug（均早于 2.0.1 存在，非本次同步改动引入）。

### ① 备份导入整份失败（含三盲的备份 100% 导入不了）
- **根因**：`parseOwnJson` 里分组容器初始化写死 `{ "3x3":[], "2x2":[] }`，**缺 `bld` 键**。
  备份文件只要含三盲分组（`events.bld.groups` 非空），`v2["bld"].push(...)` 抛 TypeError
  → `importFile` 的 `try/catch` 吞掉 → 弹「导入失败：无法解析文件内容」。
  **不是只丢三盲，是整份文件全丢**。
- **修复**：新增 `EVENT_KEYS = EVENTS.map(...)` 与 `emptyEventsObj()`，
  导入/迁移/合并/结果提示一律由 `EVENTS` 派生，不再写死项目列表。
- **顺带修掉同类隐患**：`importFile` 与测试钩子 `mergeTxt` 的 picks 只遍历 3x3/2x2
  （三盲分组会被静默跳过）；`migrateV1` 也只迁 3x3/2x2。
- 唯一保留的写死：`csTimerPayload` 仍只导出 3x3/2x2 —— 这是**故意的**，csTimer 无三盲类型。

### ② csTimer 往返导入不幂等（同一文件导入两次成绩翻倍）
- **根因**：`csTimerSolve` 导出时少写「打乱」槽位，只输出 3 元素
  `[[pen,ms], note, ts]`，而解析器按 csTimer 官方 4 元素读 `e[3]` 取时间戳 →
  取不到 → `normSolve` 用 `Date.now()` 兜底 → 每次导入成绩签名都不同
  → `sigIndex` 去重失效 → 重复导入条数翻倍（17 → 34）。
- **修复**：导出补齐 4 元素（`[[pen,ms], 打乱, 备注, 时间戳]`）与官方对齐；
  解析器同时兼容 3 元素（历史文件）与 4 元素两种格式。
- **附带好处**：往返导入的成绩保住真实时间戳，不再被 `Date.now()` 冲掉。

## 版本规则
- **MAJOR**：不兼容的架构/数据口径变更（读码口径、难度分公式、存储结构重构）
- **MINOR**：向后兼容的功能新增（新增训练模块、新增配色方案）
- **PATCH**：向后兼容的缺陷修复

> 每次合并到 `main` 前，必须在此文件顶部追加对应条目；版本号变更同步写入 `docs/VERSION`。
