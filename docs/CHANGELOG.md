# 更新日志 / Changelog（fto-site 魔方训练站）

本文件记录站点版本变更，版本号遵循 [语义化版本 2.0.0](https://semver.org/lang/zh-CN/)。

**协作约定**
- `main` 分支始终为可上线稳定版；新功能在功能分支开发，合并进 `main` 时在本文件顶部追加条目。
- 每次发布打 `v<版本号>` 轻量标签（如 `v1.0.0`），标签仅本地留存或经确认后推送。
- 破坏性数据口径变更（读码口径、难度分公式、存储结构）必须升级 MAJOR 并写明迁移说明。

## [2.0.21] — 2026-10-18（修复 · 盲拧训练连续两题不考同一角块/棱）

用户反馈练习时「连续两道题有时会考同一个角块（同一考点）」。根因：原 `genQuiz()` 每题的角块/棱索引 `ci`/`ei` 都是独立随机，理论上会连续重复（6 个角块里约 1/6 概率连号）。

修复（`tools/corner-trainer/index.html`、`tools/edge-trainer/index.html` 同源同步）：
- **练习模式**：出题时排除上一题的角块/棱，从其余候选里随机，连续两题必定不是同一个角块/棱；分布仍均匀。
- **复习错题模式**：优先从「非上一题角块」的错字里抽；若该角块是错字池里唯一来源才回退全池（避免死循环），绝大多数情况同样不连号。
- 逻辑层验证：各 20 万次出题，连续重复次数 = 0。

## [2.0.20] — 2026-10-18（修复 · 盲拧训练页红/橙配色区分度不足）

用户反馈「角块训练页面里红色和橙色区分不明显，有人反映看不清楚」。实测确认问题真实存在：原用魔方官方贴纸色 **红 `#C41E3A` / 橙 `#FF5800`**，两者对比度仅 **1.85:1**（属于「必须并排细看才分得出」），而编码对照表里的字母片只有 15px 小，根本来不及并排比对。

- **配色调整**：红 `#C41E3A` → **`#A31229`（深酒红）**；橙 `#FF5800` → **`#FF8A1F`（亮橙）**。
  - 红↔橙对比度 **1.85 → 3.33:1（+80%）**，15px 小色块上也能一眼分辨；
  - 橙↔黄仍保留 1.66:1，不会与黄色混淆；黄 / 白 / 绿 / 蓝四色沿用官方色不变；
  - 字母片文字色**无需改动即自动适配**：`needsDarkText()` 按感知亮度阈值 100 判定，新橙（160.8）走深色字（对比 7.50:1）、新红（64.0）走白色（对比 7.85:1），均优于调整前。
- **棱块训练页同步**（两页同源，色值必须一致）：12 组中「红绿 FR」「橙绿 BR」「橙蓝 BL」过去最容易混淆；角块页「黄红蓝」的 B 与「黄橘绿」的 H 也彻底分开。
- **代价说明**：调整后颜色不再等于官方贴纸色，与实物略有偏差。这是有意的取舍 —— 该页面用途是编码辨识训练，**辨识度优先于色值标准**。
- 验证：`verify_blind_trainers_mobile.py`（两页 × 4 视口 × 4 面板）全部通过；浏览器实测渲染色为 `rgb(163,18,41)` / `rgb(255,138,31)`，无旧色残留。

## [2.0.16] — 2026-10-17（功能 · 盲拧角块/棱块训练页手机端一屏适配 + 独立 PWA；OLL 桌面端 57 卡一屏铺满）

用户诉求：「角块训练和棱块训练这两个页面做手机端优化，做成 PWA 形式，手机端在一个页面完整显示全部内容、不需要上下滚动，像小程序一样」。

### 盲拧训练页一屏适配（`tools/corner-trainer/` + `tools/edge-trainer/`）

两页为同源克隆（同 id、同函数名，`drawCorner` ↔ `drawEdge`，canvas 同 id）。改动前**两页都完全没有布局引擎**（无 `innerHeight` / `@media` / `fitBoard`），纯文档流：角块页手机端溢出 259px、棱块页溢出 825px（iPhone SE），题图被挤出屏幕。

- **新增一屏适配层**（`body.ct-single-screen` / `body.et-single-screen`，作用域仅本页）：
  - body 锁定 `100dvh` + `overflow:hidden`，**页面自身不再出现纵向滚动条**（用 dvh 而非 innerHeight —— 移动端地址栏收放时 innerHeight 会跳）；
  - 单屏模式下**隐藏页脚**（130px + 64px 上边距 = 194px，占原溢出 75%，是最大头）；
  - **canvas 按容器可用空间等比缩放并重绘**：两页的 `drawCorner` / `drawEdge` 内部都按 `canvas.width/height` 计算（`Math.min(W,H)*k`），所以改尺寸后重绘即自适应、不变形；退出单屏模式时还原原始 340×300 / 340×240，避免桌面端题图被拉伸；
  - 字号与间距全部使用 `clamp(..., vh, ...)` 随视口高缩放，**不写死像素断点**，iPhone SE 到 iPad 竖屏通用；
  - **编码对照表改网格排布**：角块 6 组改两列（6 行 → 3 行，280px → 97px），棱块 12 组改三列（12 行 → 4 行）；是否启用网格**由「高度装不装得下」决定**（早期版本按 `innerWidth` 阈值判断方向错了 —— iPad 竖屏 768 宽但棱块单列 12 行装不下）。实在放不下才退化为表内滚动。
  - 错题列表 / 练习记录同理：超高时容器内滚动，页面本身不滚。
- **新增独立 PWA**：每页各自 `manifest.webmanifest` + `sw.js`，可「添加到主屏幕」像小程序一样全屏离线打开；补 `theme-color` / `apple-mobile-web-app-capable` / `mobile-web-app-capable` / `apple-mobile-web-app-status-bar-style` / `apple-touch-icon` / `viewport-fit=cover`。
- **修复浅色主题下错题行看不清**：`.review-item` 字色 `var(--surface-2)`（浅灰）压在 `--red-soft` 淡红底上几乎不可读，改为 `var(--fg)`。

### OLL 桌面端 57 卡一屏铺满（`tools/cfop/oll-trainer.html`）

- **根因**：`MIN_CELL = 132` 被当作**硬下限**，而 OLL 有 57 张卡（PLL 仅 21 张），在 1440×900 可用区（1134×496）下任何列数都排不下 → 所有方案被否决 → 落到 `fallback(fitsH:false)` → `overflowY` 不设 `hidden` → **整页溢出 967px**。
- **修复**：区分「理想尺寸 `minCell`」与「硬下限 `minCellFloorFor(n, isNarrow)`」（>40 张时降至 88）；先按理想值搜一轮，失败再按硬下限重搜（**列数上限须按本轮下限重算**，沿用旧上限等于白搜）。
- **卡片减负**：公式行移入练习浮层（`title` 与浮层本就含子分组与全部公式，不丢信息），保留「预览图 + 名称 + 子分组 + 成绩」；子分组移到名称下方独立一行；名称字号由 JS 按实际卡宽反推（`--oll-name-fs`），否则双位数「OLL 10」在 ~100px 卡里被裁成「OLL 1(」。
- **卡片数 > 40 时隐藏页脚**：页脚 181px 会吃掉 43% 的视口高度，使可用高度从 613px 掉到 496px、每张卡被压到 72px（预览图消失）—— 这是最大杠杆。
- 结果：溢出 **967px → 2px**，10 列 × 6 行、每格 103px，**OLL 1~57 全部完整可读**；PLL 页（21 张）完全不受影响。

### 三个 PWA 作用域隔离
`sw.js`（`fto-timer-v15`，scope `/`）· `tools/corner-trainer/sw.js`（`fto-corner-v1`）· `tools/edge-trainer/sw.js`（`fto-edge-v1`）。各 SW 激活时**只清理自己前缀**的旧缓存，绝不误删其他 PWA；`install` 阶段逐个 `cache.add` 并吞掉个别错误（`cache.addAll` 会因单个 404 整体失败）。

### 验证
`verify_blind_trainers_mobile.py`：两页 × 4 视口（375/390/430/768）× 4 面板（首页/答题/结果/记录）均 `docH == innerH` 零溢出、对照表齐全且无需滚动、canvas 未超容器且保持原始比例、答题流程走通、桌面端不启用单屏且原布局不变、9 项 PWA 标签齐备、三个 SW 缓存名互不相同 —— **全部通过**。

## [2.0.14] — 2026-10-16（修复 · hold-to-start 计时三处缺陷；矩阵/看板视觉重构：快慢改字色、卡片去公式）

用户实际使用「高阶翼棱」练习页反馈：计时器延时不灵敏、停表后第一次总不显示、看图页面要刷新才有效果；并提出矩阵布局保留、快慢改用字体颜色体现、卡片不写公式直接显示位置码（B行M列 → BM）。修复与改造**三页同步**（`tools/4bld/wing.html` 翼棱、`tools/4bld/index.html` 440 中心块、`tools/scramble-uf440/index.html` UF440）。

**修复**
- **计时器长按不灵敏（根因：repeat 分支清掉计时器且不重建）**：`pKeydownHold()` 中「长按中保持」分支原实现为 `clearTimeout(pPrep)`——真实浏览器长按会持续派发 `keydown`（autorepeat），repeat 到来时把 prep 计时器清掉且不重建，导致**按住再久都到不了 green、松手即取消**，完全无法开始计时。现改为该分支直接返回（幂等，等原计时器自然到点）。另注意：绑定处的 `!e.repeat` 过滤不可靠（浏览器只对真实按住置 `repeat`），防御必须落在 `pKeydownHold` 自身。
- **停表后成绩不显示（根因：只重绘看板不重绘矩阵）**：`pStopTimer()` 原先只调用 `renderBoard()`，在矩阵总览视图下成绩虽已写入 localStorage，但格子 / KPI / TOP10 不更新，表现为「计时后不显示，要刷新页面才生效」。现改为 `renderCurrent()` 按当前视图重绘；删除成绩、清空成绩两处同步修正。
- **响应速度**：hold 时长 500ms → 300ms（仍足够避免误触）。
- **翼棱新增全屏计时器点击启停**：全屏计时器（`#c4-fs-timer`）也可点击开始/停止，与空格键等效。

**视觉重构**
- **快慢改用字体颜色体现**：`colorByRatio()` 由「连续渐变色背景 + 按亮度反算字色」改为输出 **7 阶离散字色** `var(--spd-t0..6)`（JS 只计算档位索引，色值全部走 CSS 变量；深色主题用亮色系、浅色主题同色相压暗一档，**切换主题即时生效、无需重渲染**）。连续渐变色背景仅保留给仪表盘图例。矩阵格与看板卡片的内联样式**只保留 `color`** 不再写 `background`——**底色表达「是否练过」，字色表达「快慢」**，两层信息不互相干扰。

## [2.0.2] — 2026-10-10（补丁 · 修复备份导入整份失败 + 往返导入翻倍）

> 数据找回过程中的连带修复。用户在恢复 23,895 条成绩的备份时导入报「无法解析文件内容」，
> 顺藤摸出的两个既有 bug（均早于 2.0.1 存在，非本次同步改动引入）。

### ① 备份导入整份失败（含三盲的备份 100% 导入不了）
- **根因**：`parseOwnJson` 里分组容器初始化写死 `{ "3x3":[], "2x2":[] }`，**缺 `bld` 键**。
  备份文件只要含三盲分组（`events.bld.groups` 非空），`v2["bld"].push(...)` 抛 TypeError
  → `importFile` 的 `try/catch` 吞掉 → 弹「导入失败：无法解析文件内容」。
  **不是只丢三盲，是整份文件全丢**。
- **修复**：新增 `EVENT_KEYS = EVENTS.map(...)` 与 `emptyEventsObj()`，
  导入/迁移/合并/结果提示一律由 `EVENTS` 派生，不再写死项目列表。
- **顺带修掉同类隐患**：`importFile` 与测试钩子 `mergeTxt` 的 picks 只遍历 3x3/2x2
  （三盲分组会被静默跳过）；`migrateV1` 也只迁 3x3/2x2。
- 唯一保留的写死：`csTimerPayload` 仍只导出 3x3/2x2 —— 这是**故意的**，csTimer 无三盲类型。

### ② csTimer 往返导入不幂等（同一文件导入两次成绩翻倍）
- **根因**：`csTimerSolve` 导出时少写「打乱」槽位，只输出 3 元素
  `[[pen,ms], note, ts]`，而解析器按 csTimer 官方 4 元素读 `e[3]` 取时间戳 →
  取不到 → `normSolve` 用 `Date.now()` 兜底 → 每次导入成绩签名都不同
  → `sigIndex` 去重失效 → 重复导入条数翻倍（17 → 34）。
- **修复**：导出补齐 4 元素（`[[pen,ms], 打乱, 备注, 时间戳]`）与官方对齐；
  解析器同时兼容 3 元素（历史文件）与 4 元素两种格式。
- **附带好处**：往返导入的成绩保住真实时间戳，不再被 `Date.now()` 冲掉。
