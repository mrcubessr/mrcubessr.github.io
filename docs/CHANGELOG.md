# 更新日志 / Changelog（fto-site 魔方训练站）

本文件记录站点版本变更，版本号遵循 [语义化版本 2.0.0](https://semver.org/lang/zh-CN/)。

**协作约定**
- `main` 分支始终为可上线稳定版；新功能在功能分支开发，合并进 `main` 时在本文件顶部追加条目。
- 每次发布打 `v<版本号>` 轻量标签（如 `v1.0.0`），标签仅本地留存或经确认后推送。
- 破坏性数据口径变更（读码口径、难度分公式、存储结构）必须升级 MAJOR 并写明迁移说明。

## [2.0.63] — 2026-10-30（24点训练：求解器内核 · 五级题库 · 双模式训练 · 错题云同步）

用户诉求：「做一个 24 点训练功能，能求四个数算 24 的全部加减乘除算法（含无解判定），题库按难度分五级，支持十题计时与三分钟闯关两种训练模式，并记录错题、可只刷错题、有数据汇总。」

- **求解器内核（GitHub 复用 + 改写，精确分数）**：vendored 到 `assets/vendor/suan24/suan24.js`，合并 `seekerlee/suan24`（WTFPL，精确分数引擎、递归枚举全部解）与 `Yuanbest583/24GameSolver`（MIT，项收集规范化去重 / 去括号）。API：`Suan24.solve(nums)` 求全部解并返回结构元数据（`requiresFraction` / `usesDivision` / `anyNegative` / `count`），`Suan24.checkAnswer(nums, expr)` 校验用户算式（须恰好用完四数各一次且结果 = 24）。UMD 双端（浏览器 + Node 生成脚本）可用，不引外部 CDN。
- **五级题库（双数字范围）**：生成器 `tools/24game/gen-bank.js` 枚举 1–10 与 1–13 两个范围的四数组合，跑求解器按**解的结构**判定难度，导出 `tools/24game/data/levels.json`。分级标准：L1 纯 +−× 且解≥6；L2 纯 +−× 解 3–5 或整除解≥4；L3 纯 +−× 解≤2 或整除解 2–3；L4 全程整数但必须用整除除法；L5 必须用分数中间值（最难，如 3,3,8,8）。题量（1–13 / 1–10）：211/300/300/144/55 与 91/191/222/39/22，训练时洗牌保证不重复。
- **训练系统（三页签：求解 / 训练 / 统计）**：`tools/24game/index.html` + `game24.js` + `game24.css`。
  - 求解页：输入四个数，列出全部算法；无解明确提示。
  - 训练页：数字范围（1–10 / 1–13）× 五级 / 随机 / 全部 × 两种模式（**十题计时**、**三分钟挑战**）× 题库来源（系统题库 / **只刷错题**）× 可选**混入无解题**（需点「此题无解」确认）；用户输入算式即时判对错，可「看答案」「不会跳过」。
  - 统计页：总览（总练习次数 / 总题数 / 总正确率 / 十题最快 / 三分钟最高 / 各级正确率）、**错题本**（按题记录尝试/错次、上次错答、最后错时间，可重练 / 移除已掌握 / 清空）。
- **数据云同步**：错题 `game24_wrong_v1` 与统计 `game24_stats_v1` 通过 `LSProvider` 注册进同步白名单，随账号云同步（复用既有同步机制，不新增 LS key 之外的通道）。
- **导航与首页接入**：`assets/js/site-nav.js` 教练分组加「24点训练」入口；`index.html` 首页教练区块加卡片。两文件均在 PWA `APP_SHELL` 内，故同步递增 `sw.js` `CACHE` 至 `fto-timer-v38`（见 `docs/sw-changelog.md`）。
- 验证：Playwright 真实浏览器冒烟全过（求解、十题全对、错题记录、只刷错题、三分钟记录），0 pageerror；求解器 Node 单测覆盖 `3,3,8,8`（唯一分数解）、`1,1,1,1`（无解）、`4,4,4,4`、`1,5,5,5`（5×(5−1/5)）。

## [2.0.61] — 2026-10-29（首屏优化一期 · 二阶盲拧「编码转打乱」工具 · sw 注释外迁）

- **二阶盲拧「编码转打乱」工具（全新页 `tools/2bld/`）**：新增页面 `tools/2bld/index.html` 与核心模块 `assets/js/bld2-core.js`，并在 `assets/js/site-nav.js`（在 `APP_SHELL` 清单内）「魔方教练工具箱 → 公开工具」中 bldscramble 之后挂上入口「二阶盲拧打乱」。与已有 `tools/bldscramble/` 的 2×2 能力互补：那个工具按「错位角块数 k + 翻色数 f」参数化**随机生成**，本工具按用户给的具体编码**精确反解**打乱。
  - 核心能力：`codeToScramble`（编码 → 打乱公式）、`scrambleToCode`（打乱 → 编码）、`stateToCode`（状态 → 编码）、二阶专用 IDA* 求解（cp 40320 × co 2187 双剪枝表，BFS 建表 ~250ms，最优解 ≤ 11 步，单次求解 < 20ms，建表放 `requestIdleCallback` 预热不阻塞首屏）。
  - 实现要点：① 位置编码与朝向编码**分离读取**——先「摆正」（untwist）得到纯位置置换再读码，长度必然 ≤ 7，扭角另用「位置字母 + 扭数」标注（如 `G1` = UBR 位置的角扭 1 次）；② 二阶角状态为奇置换时三阶 min2phase 需人为交换两棱、解会膨胀到 18~20 步，故改用二阶专用 IDA*；③ 扭角总和必须是 3 的倍数（二阶物理约束），不满足直接给中文提示而非返回「打乱后读不回来」的公式；④ 缓冲块 J 归位时循环起笔有歧义，默认按盲拧习惯优先「缓冲参与」，另给「这一把的缓冲块 J 已经归位」勾选项走另一分支；⑤ 同一角的三个字母连成一段（如 `ABC`）实为扭角而非位置循环，直接判非法并提示改写到扭角栏；⑥ 页面按钮用私有的 `.gbtn` 系列，避免 `components.css` 里 `.btn:hover` 的特异性把实心蓝按钮冲成浅灰。
- **首屏优化一期（全站 118 页）**：`.pc` 之外的 119 个 HTML 页面统一重排 `<head>`——把 `theme.js` / `palette.js` 从 head 的阻塞加载下沉到 `body` 末尾，head 内联一段约 300 字节的同步主题判定脚本（读取 `theme` / `mf_palette` 并直接写 `data-theme` / `data-palette`），既消除主题闪烁又不阻塞首屏；`sync-boot.js` 仍按规矩留在 head 同步引入（页面内 `SyncBoot.ready(...)` 是紧跟它执行的内联脚本，延后会 ReferenceError）。
- **`assets/js/sync-boot.js` 启动策略并行化**：原来 8 个同步模块用 `chain.then(loadScript)` 逐个串行加载 = 8 次串行往返，弱网下光排队就 1 秒以上；现改为「并行下载 + 按序执行」（动态插入的 `<script>` 设 `async=false` 即 in-order），8 次往返压成 1 次，执行顺序与原来完全一致；单个文件加载失败只记录不再中断整条链；启动时机从「立即」改为 DOMContentLoaded 后的空闲时段（`requestIdleCallback`，200ms / 2s 双兜底），`SyncBoot.ready()` 此前已可用、回调照常排队，flush 时统一执行，页面侧完全透明。
- **`sw.js` 历史注释外迁**：原本堆在 `sw.js` 顶部约 150 行的版本变更注释（v8 ~ v37）迁到新建的 `docs/sw-changelog.md`，代码从第 164 行才开始、文件由 313 行缩到 172 行。**版本管理规则不变**：凡是改动 `APP_SHELL` 清单里的文件都要递增 `CACHE` 常量。
- `sw.js` `CACHE` 递增至 `fto-timer-v37`（`site-nav.js` 在 `APP_SHELL` 内且已改）；新页面 `tools/2bld/` 与 `bld2-core.js` 不进预缓存清单，走运行时缓存（stale-while-revalidate）。
- 验证：本地 Playwright 实测 33 项（首屏优化一期 + 二阶盲拧功能）+ 主题路径 9 项 + 同步链路 25 项 + 抽样 14 页 HTTP 200 与主题应用全过，0 pageerror；二阶盲拧实测「编码 X → 11 步最优解」并回读校验一致、扭角和不为 3 倍数时正确拒绝、非法编码给出中文提示。

## [2.0.51] — 2026-10-21（三盲三角翻按 2 组编码计 · 难度分随锚重标）

- **根因**：`bld-engine.js` 里翻色 / 扭角的公式条数按**字母数**计（`ceil(字母数/2)`），而角色行中每个块占 2 个字母 —— 计数恰好等于块数，于是三角翻（3 块）被算成 3 条、2 翻色算成 2 条。一条翻色 / 扭转公式实际处理 **2 个块**，应按 `ceil(块数/2)` 计。
- **修复**：`flipF / twistF` 改按块数计 —— 2 翻色 = 1 条、**三角翻（3 角）= 2 条**、4 翻 = 2 条、5 翻 = 3 条。读码串与翻色检测逻辑不变，只改统计口径。
- **难度分重标**：翻色 / 扭角条数减半后加权分整体下移，`SCORE_ANCHORS` 按 2 万个 20 步 WCA 打乱重取分位：`7→0 / 12→20 / 14→40 / 15.5→60 / 17→80 / 22→100`，五档实测占比 入门19 / 初级21 / 中级18 / 高级22 / 专家21（权重不变）。
- **历史成绩迁移**：成绩记录带着 `flipLetters / twistLetters`，打开页面时按字母数反推块数自动重算（新口径成绩重算幂等）；`timer.js normDiff` 同步回传修正后的分量，不会出现「旧条数配新分数」。跨版本分数不可直接比较，同一把的档位可能变化一级。

## [2.0.10] — 2026-10-16（修复 · 翼棱公式覆盖 420 → 506，补全含 G/H 情况的旋转解析）

## [2.0.2] — 2026-10-10（补丁 · 修复备份导入整份失败 + 往返导入翻倍）

> 数据找回过程中的连带修复。用户在恢复 23,895 条成绩的备份时导入报「无法解析文件内容」，

### ① 备份导入整份失败（含三盲的备份 100% 导入不了）
- **根因**：`parseOwnJson` 里分组容器初始化写死 `{ "3x3":[], "2x2":[] }`，**缺 `bld` 键**。

- **修复**：新增 `EVENT_KEYS = EVENTS.map(...)` 与 `emptyEventsObj()`，
  导入/迁移/合并/结果提示一律由 `EVENTS` 派生，不再写死项目列表。
- **顺带修掉同类隐患**：`importFile` 与测试钩子 `mergeTxt` 的 picks 只遍历 3x3/2x2
  （三盲分组会被静默跳过）；`migrateV1` 也只迁 3x3/2x2。
- 唯一保留的写死：`csTimerPayload` 仍只导出 3x3/2x2 —— 这是**故意的**，csTimer 无三盲类型。

### ② csTimer 往返导入不幂等（同一文件导入两次成绩翻倍）
- **根因**：`csTimerSolve` 导出时少写「打乱」槽位，只输出 3 元素
  `[[pen,ms], note, ts]`，而解析器按 csTimer 官方 4 元素读 `e[3]` 取时间戳 →
  取不到 → `normSolve` 用 `Date.now()` 兜底 → 每次导入成绩签名都不同
  → `sigIndex` 去重失效 → 重复导入条数翻倍（17 → 34）。
- **修复**：导出补齐 4 元素（`[[pen,ms], 打乱, 备注, 时间戳]`）与官方对齐；
  解析器同时兼容 3 元素（历史文件）与 4 元素两种格式。
- **附带好处**：往返导入的成绩保住真实时间戳，不再被 `Date.now()` 冲掉。

## 版本规则
- **MAJOR**：不兼容的架构/数据口径变更（读码口径、难度分公式、存储结构重构）
- **MINOR**：向后兼容的功能新增（新增训练模块、新增配色方案）
- **PATCH**：向后兼容的缺陷修复

> 每次合并到 `main` 前，必须在此文件顶部追加对应条目；版本号变更同步写入 `docs/VERSION`。
