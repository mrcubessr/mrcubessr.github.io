## 2. 本地化（下载→解析）方案

`tools/cfop/scripts/fetch_cfop.py`（及专用 `fetch_f2l.py`）：

1. 请求目标页面原始 HTML；
2. 按 `<div class="row singlealgorithm">` 切分案例；
3. 提取 `data-alg`(编号)、`data-subgroup`(分类)、`setup-case`(还原打乱)、`.formatted-alg`(算法文本)；
4. F2L 每个 case 含 4 个朝向 `<ul class="list-group" data-t="F2L N,0..3">`，按 `data-t` 切分 FR/FL/BL/BR 四朝向；
5. 提取案例配图数据：OLL/PLL 取 `jcube` 的 `data-us/ub/uf/ul/ur`（→ `facelets`），F2L/AdvF2L 取 `icube` 的 `data-fl`（→ `fl`，见 `enrich_cubedata.py`）；
6. 输出结构化 JSON：`tools/cfop/data/{f2l,advanced_f2l,oll,pll}.json`。

数据已生成：OLL 57 / PLL 21 / AdvancedF2L 54 / F2L 41（四朝向齐全，共 622 条算法，0 残存 HTML）；
配图数据：OLL 57 / PLL 21 含 `facelets`，F2L 41 / AdvancedF2L 54 含 `fl`。
**重新更新数据**：`python tools/cfop/scripts/fetch_cfop.py`（或逐个 `fetch_f2l.py`），随后 `python tools/cfop/scripts/enrich_cubedata.py` 补配图数据。

## 5. 数据模型（JSON）

```json
{
  "set": "oll",
  "count": 57,
  "cases": [
    {
      "id": "OLL 1",
      "subgroup": "Dot Case",
      "setup": "",
      "facelets": { "us":"llllyllll", "ub":"…", "uf":"…", "ul":"…", "ur":"…" },
      "orientations": [ { "name": "", "algs": [ "R U2 R2 F R F' U2 R' F R F'", "…" ] } ]
    }
  ]
}
```
- F2L 的 `orientations` 有 4 项（FR/FL/BL/BR），其余集合为 1 项；
- `facelets` 仅 OLL/PLL 有（5 面 jcube 数据）；
- `fl` 仅 F2L / AdvancedF2L 有（45 字符 icube 数据：顶面 + 两可见立面 + 两隐藏面）。

### 案例配图（复刻原站 speedcubedb，`js/cube-art.js`）

原站的案例图由前端渲染，本地按其投影算法等价实现，**不使用六面展开图**：

| 集合 | 原站渲染器 | 数据 | 本项目渲染 |
|---|---|---|---|
| OLL / PLL | `jcube`（`data-us/ub/uf/ul/ur`） | `facelets` | **顶面平面示意图**：中央 3×3 顶面 + 四周一圈侧面顶层贴纸（上=ub 下=uf 左=ul 右=ur） |
| F2L / Advanced F2L | `icube`（`data-fl`，45 字符） | `fl` | **等轴立体魔方**：顶面 + 左/右两个可见立面（bilinear 投影，贴纸按面行主序） |

- 配色统一走 `tokens.css` 的 `--face-*` 六面色（`y→D 黄 / w→U 白 / g→F 绿 / b→B 蓝 / r→R 红 / o→L 橙`，`l` 为中立灰），随深浅主题自动切换；
- 等轴投影的四边形顶点取自原站 `svg.js` 输出，41 个 F2L 案例已与原站 SVG **逐格比对 0 偏差**；
- 数据补齐脚本：`scripts/enrich_cubedata.py`（从 `data/_raw/` 的原始 HTML 提取 `fl`）。

## 6. 交互功能（已落地）

- **全局搜索**：按编号 / 分类 / setup 实时过滤；
- **分类筛选**：点击 subgroup chip 快速定位（如 OLL 的「鱼形 / Dot」）；
- **F2L 朝向切换**：FR/FL/BL/BR 标签页切换；
- **点击复制**：算法与 setup 一键复制（含「已复制」反馈）；
- **掌握进度**：localStorage 持久化「★已掌握」，顶部进度条统计；
- **深浅主题**：与全站 `data-theme` 同步，记忆偏好；
- **Cross Trainer**：自选十字颜色 + 目标步数（1~8）→ `cross-solver.js` 生成十字最优解恰为该步数、且长度 ≤10 步的打乱 → `cube-art.js` 渲染**平面六面展开图**（白顶绿前标准朝向）→ 醒目的「白顶绿前」朝向提示 → 空格键计时 → 一键复制当前打乱 → 可批量生成 10 个同设置打乱并逐条复制。详见 §7。
- **PLL 打印页生成器**（`js/pll-print.js` + `css/pll-print.css`）：见 §6.1。

### 6.1 PLL 打印页生成器

入口：PLL 页工具条右侧「🖨 生成打印页」→ 打开弹窗（左侧配置 / 右侧 A4 实时预览）。

- **自选情况**：21 个 case 逐个勾选；快捷条支持 全选 / 清空 / 反选 / 按分类整组切换（Adj Swap 12 · Opp Swap 5 · EPLL 4）；
- **自选公式**：每个 case 一个下拉，从源站 4 条算法中任选 1 条（下拉内展示完整公式，悬停亦有提示）；
- **自动排版**：按「列 × 行」分页，预设 6 档——
  | 预设 | 列×行 | 每页 | 21 例页数 |
  |---|---|---|---|
  | 一页速查 | 3×7 | 21 | 1 |
  | 标准 | 3×4 | 12 | 2 |
  | 大图 | 2×4 | 8 | 3 |
  | 横版 3/4/5 列 | 3×3 / 4×3 / 5×4 | 9 / 12 / 20 | 3 / 2 / 2 |
  另可自定义列（1–6）与行（1–10）、竖版/横版 A4；
- **纸面内容开关**：配图 / 编号 / 分类 / 公式 / 页眉（标题 + 页码 + 姓名日期栏）逐项可关，标题文字可编辑；
- **预览缩放**：适应宽度 / 100% / 75% / 50%；
- **打印**：`window.print()`，动态注入 `@page { size: A4 portrait|landscape; margin: 0 }`；打印时隐藏站点外壳与全部交互界面，只输出 A4 纸张；
- **记忆**：勾选、公式、排版选择全部存入 `localStorage`（`cfop-pll-print-v1`），下次打开即恢复。

> 实现要点（踩坑记录）：纸张用 `height:297mm + overflow:hidden`，且配图容器 `.pp-cell__art` 必须 `flex:1 1 0` + 内部 `svg` 绝对定位。若让 svg 参与普通流，其固有尺寸会形成「布局溢出」，Chrome 分页据此为每页多输出一张空白页（已纳入回归断言：**PDF 页数 == 预览页数**）。

## 7. Cross Trainer 设计

复刻 `speedcubedb.com/cross/?trainer=cross` 的核心用法：**选定十字颜色 + 目标步数 → 生成打乱**，
并追加约束「**打乱长度 ≤ 10 步**」（原站未限制，用户明确要求）。

### 7.1 控件

| 控件 | 取值 | 说明 |
|---|---|---|
| 十字颜色 | 白 / 黄 / 绿 / 蓝 / 红 / 橙 | 带色点，写本地 `localStorage`（`cfop-cross-trainer-v1`） |
| 目标步数 | 1 ~ 8 | 「做十字所需的最优步数」，8 是理论最大值（God's number for the cross） |

生成后显示：**打乱公式**、**白顶绿前朝向提示**、**平面六面展开图**、可选展开的「十字解法」、
「换一个打乱 / 复制 / 批量 10 个」按钮；空格键计时。不再显示打乱长度徽章与步数解释副标题。

### 7.2 贴纸模型（`js/rubik-core.js`）

54 贴纸（6 面 × 9 格，行主序），标准约定 U=白 R=红 F=绿 D=黄 L=橙 B=蓝。
6 个基本转动全部按「**环序法**」重新推导（以该面自身 net 视图为基准，用环序 + 四分之一圈统一定向）。

> ⚠️ **踩坑记录（重要）**：旧版 `cross-trainer.js` 内嵌的模型 **U / R / L 三个转动方向错误**，
> 且 D / F / B 的相邻条带内部顺序反转，会生成**现实中不存在的魔方状态**（即"3D 图是假的"）。
> 现已删旧模型、统一改用 `rubik-core.js`，并以 **pycuber 逐贴纸交叉校验**作为长期回归防线：
> `python tools/cfop/scripts/verify_cube_model.py`（29 条定式 + 300 组随机 1~25 步，全贴纸一致）。

### 7.3 十字求解与打乱生成（`js/cross-solver.js`）

1. 从贴纸模型推导 18 个转动对 **12 个棱块槽位**的置换 `PERM` 与翻转 `FLIP`；
2. 只跟踪十字色的 4 个棱块，状态编码 = 4 个 base24 位（`槽位×2 + 朝向`），规模 24⁴ = 331776，**可达 190080**；
3. 从还原态 BFS 得到「到十字复原的最优步数」表（**半步制**，R2 记 1 步）：

   ```
   0:1  1:15  2:158  3:1394  4:9809  5:46381  6:97254  7:34966  8:102
   ```

   （与公开理论值一致；最大 8 步。首次建表约 70 ms，按颜色惰性构建并缓存。）
4. **打乱生成策略**：
   - `N ≤ 7`：**拒绝采样** —— 随机生成 5~10 步合法打乱，取十字最优步数恰为 N 的。
     实测命中率（10 步打乱）：N=1 0.78% / N=2 5.7% / N=3 17.9% / N=4 28.9% / N=5 29.4% / N=6 16.0% / N=7 1.33%。
   - `N = 8`：在 ≤10 步打乱下命中率 < 2.5e-6，**拒绝采样不可用**，改用**构造法**：
     取一个最优 8 步的状态 → 其最优解反序取逆即为「还原态 → 该状态」的打乱基底 →
     再插入「**十字恒等步**」（十字棱块所在层之外只有对面层，对面层转动不改变十字的槽位与朝向）
     把长度凑到目标，且最优步数不变。
5. **解法**为随机化贪心下降，等优候选里优先挑「不与上一步同面/对面」的，使解法与被反推的打乱都保持 WCA 风格。

> 该方法学正确性由**两条完全独立的推导**相互印证：
> ① `cross-solver` 的置换表 → `LO/HI` 转移 → BFS；② `rubik-core` 贴纸模型直接 BFS。
> 全量 190080 状态**逐状态比对 0 处不一致**，目标态唯一。
> `node tools/cfop/scripts/test_cross_solver.js` 默认校验深度 ≤5（5.8 万状态，1~2 秒）；
> 全量用 `CROSS_DEEP=1` 运行（约 25 秒）。

### 7.4 可视化与交互

- 由 `js/cube3d.js` 渲染**立体魔方**（正投影 + 背面剔除 + 画家算法，非展开图）；
- 默认视角**从下往上**（yaw −45° / pitch −40°）：**底面朝向观察者**，底层十字一目了然；
- **可拖拽旋转**（鼠标 / 触摸，clamp pitch ±89°），转到任意角度即可看到全部 6 面；
- **「对准十字色」按钮**：只改相机角度（不改魔方朝向），正对所选十字色的那个面，
  正投影下只显示该面 1 个面（1 底 + 9 贴纸），方便检查十字形态；手动拖拽会自动退出该模式；
- 计时：`requestAnimationFrame`，空格开始 / 暂停（在按钮、输入框上按空格不触发，避免与控件冲突）。
- 3D 外链：`https://www.cubedb.net/?puzzle=3&scramble=…`。

### 7.5 踩坑记录

- **`.seg__btn` 的选中态约定**：站内约定用 `.is-active` 类表达，`assets/js/site-nav.js` 会
  用 MutationObserver 把类名镜像成 `aria-pressed`。该镜像原先只认 `.active`（认不出 `.is-active`），
  导致 `aria-pressed` 恒为 `false` —— 而 `components.css` 里 `.seg__btn[aria-pressed="true"]`
  才是选中态样式，于是**选中项在视觉上完全看不出来**。已修正 `syncToggleAria` 同时识别两种类名（全站收益）。
- **`hidden` 属性会被 `display` 覆盖**：`.ct__solution{display:flex}` 的优先级高于 UA 的
  `[hidden]{display:none}`，导致「解法」面板永远可见（训练时等于直接给答案）。
  站内既有约定是显式写 `.X[hidden]{display:none}`（见 `pll-print.css` 的 `.pp-modal[hidden]`、
  `3x3teach/css/style.css` 的 `.modal[hidden]`），本页已照做。
- **计时器无 `color` 声明**会继承到次要文字色，浅色主题下对比度不足；已显式 `color:var(--fg)`。
